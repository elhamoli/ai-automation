## الفكرة

**RED DISH** نموذج لأتمتة عمليات مطعم افتراضي للأكل الحار باستخدام **n8n**. بيربط محادثة العميل على Telegram بالطلب، وخدمة العملاء، وتسجيل البيانات، وإشعارات المطبخ، وتحليل تقييمات ما بعد التوصيل.

## رحلة العميل

![مراحل رحلة العميل الخمسة](assets/customer-journey.svg)

| المرحلة | دورها |
| --- | --- |
| بداية المحادثة | عرض اختيارات الطلب والمنيو والأسئلة على Telegram. |
| عرض المنيو | جلب صورة المنيو وإرسالها للعميل. |
| الطلب والدعم | وكيلان باستخدام Gemini، واحد للطلب وواحد للأسئلة، مع ذاكرة للمحادثة. |
| عمليات المطعم | Google Sheets لتسجيل البيانات وGmail لإشعارات المطبخ وتحديثات الطلب. |
| التقييم | انتظار 60 دقيقة في مسار المتابعة، ومسار منفصل يقرأ تقييمات الشيت ويصنّفها ويوجّه التنبيهات. |

## تبدأ منين؟

ابدأ بملف [`RED DISH last.json`](RED%20DISH%20last.json): فيه 33 عقدة، منهم خمس ملاحظات بتشرح المراحل. النسخة الأقدم محفوظة للمقارنة.

1. استورد الملف باستخدام **Import from File** داخل n8n.
2. اربط حسابات Telegram وGemini وGoogle Sheets وGmail الخاصة بالتجربة.
3. اضبط الشيتات وحقول التسجيل والجلسات ومسارات الرسائل حسب [دليل الإعداد](docs/SETUP.md).
4. جرّب الحالات الموجودة في [دليل الديمو](docs/DEMO.md) قبل التفعيل.

**الحالة الحالية:** نموذج Portfolio يحتاج إعداد واستكمال قبل التشغيل الفعلي. النسخة الأصلية فيها قيم مرتبطة ببيئة المطوّر، وحقول تسجيل غير مكتملة، وبعض المراجع والمسارات محتاجة ضبط. ملفات الـ workflow الأصلية محفوظة كما هي، والتوثيق بيوضح المطلوب. لم يتم التحقق من التشغيل الكامل على الخدمات الحقيقية ضمن هذا التحديث.

تصنيف التقييم بيوجّه المشكلة للمطبخ أو التوصيل أو الإدارة، لكنه مش إثبات لسبب المشكلة. سؤال الأكل الحالي بيتكلم عن درجة الحِرّاقة، فلازم يتراجع قبل اعتباره مقياس رضا عام.
